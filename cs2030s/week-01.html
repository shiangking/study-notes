Week 1: Functions, Encapsulation & OOP Basics

Module: CS2030S Programming Methodology II • Generated Study Notes

📌 1. High-Yield Summary

  • Functions as Abstraction: Decouples what a computation does from how it is implemented, providing a clear abstraction barrier between client and implementer.
  • Encapsulation: Bundles state (fields/attributes) and behavior (methods) together within a class to protect internal data integrity.
  • Primitive vs. Reference Types: Primitives hold raw binary values directly in memory; reference types store memory addresses pointing to heap-allocated objects.
  • Aliasing: Multiple reference variables pointing to the same object on the heap can cause unintended state mutation across aliases.
  • Initialization Rules: Local variables must be manually initialized before read (compile-time error), while object fields are auto-initialized by the JVM to default values (primitives to 0/false, references to null).

🧠 2. Core Concepts & Deep-Dive Breakdown

A. The Abstraction Barrier

An abstraction barrier enforces separation of concerns between callers and implementers:

+-------------------------------------------------------------+
|                     CLIENT (Caller)                         |
|   Concern: WHAT the function does (Contract & Types)        |
+=============================================================+
|                 [ ABSTRACTION BARRIER ]                     |
|           (Enforced by Return & Parameter Types)            |
+=============================================================+
|                   IMPLEMENTER (Callee)                      |
|   Concern: HOW the function executes (Algorithm & State)    |
+-------------------------------------------------------------+

B. Encapsulation in Java

class Circle {
    // Fields / Properties (State)
    double x;
    double y;
    double r;

    // Method (Behavior)
    double getArea() {
        return 3.14159265359 * r * r;
    }
}

// Usage:
Circle c = new Circle();
c.r = 10;                // Auto-widened from int (10) to double (10.0)
double area = c.getArea(); // Returns 314.159...
Conceptual Trigger OOP Representation Example
Noun with state/actions Class User, Booking, Point
Adjective / Property Field double radius, String name
Verb / Action Method makeBooking(), getArea()
Single primitive value without behavior Existing primitive type int count

C. Reference Types & Memory Aliasing

Circle c1 = new Circle();
Circle c2 = c1; // Aliasing: both variables hold the exact same address

c1.r = 10.0;
System.out.println(c2.r); // Prints 10.0 (mutating c1 affects c2)
Variable Category Initialization Rule Uninitialized Result
Local Variables Must be explicitly initialized prior to read. Compile-Time Error
Primitive Fields Auto-initialized by the JVM. 0, 0.0, false
Reference Fields Auto-initialized by the JVM. null (Causes runtime NullPointerException if dereferenced)

⚠️ 3. Exam Traps & Common Pitfalls

# Trap / Misconception Root Cause Remedy
1 Unintended Aliasing Mutation Assuming c2 = c1 creates a duplicate circle object. It only copies the reference pointer. Instantiate a new instance (e.g., new Circle(...)) when distinct state is required.
2 Dereferencing null Fields Assuming object field references are initialized automatically upon class creation. Always initialize reference fields inside constructors or declarations.
3 Direct Field Exposure Exposing raw fields (c.r = 10;) breaks encapsulation. Use private access modifiers with accessor/mutator methods.

💡 4. Active Recall Flashcards

Question Answer
What primary role does a function's type signature play in OOP? It establishes and enforces the abstraction barrier between client and implementer.
What is the default initial value of an uninitialized reference field in a class? null
When two variables hold references to the identical object, what is this called? Aliasing
What occurs when attempting to read an uninitialized local reference variable? Compile-Time Error (variable might not have been initialized)
What occurs when calling a method on an uninitialized reference field? Compiles successfully, but throws a NullPointerException at runtime.
