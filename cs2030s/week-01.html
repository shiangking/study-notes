CS2030S Guide: Functions, Encapsulation, and OOP Basics

Primary source: Week 1 lecture notes, Units 3–4. This guide preserves the course ideas and code patterns, while adding connective explanations for exam revision.

1. In-depth summary & concept fundamentals

Functions act as abstraction mechanisms that separate what a computation does from how it is implemented. This creates a clear boundary—an abstraction barrier—between clients and implementers. In Java, this barrier is strongly enforced through return types and parameter types.

Encapsulation takes this a step further by bundling composite data types (fields/attributes) with the functions (methods) that operate on them into a Class. An instantiated class is an Object, which maintains the integrity and consistency of its own internal state.

Java distinguishes between primitive types (which directly store their literal values) and reference types (which store memory addresses pointing to objects in the heap). When two reference variables point to the same object, they create an alias. Mutating the object via one reference causes the change to be visible through all other references, which is a major source of bugs.

2. Core concepts & deep-dive breakdown

Defining composite data types and classes

When modeling real-world entities, we map nouns to classes, adjectives to fields, and verbs to methods:

class Circle {
  double x;
  double y;
  double r;

  double getArea() {
    return 3.14159265359 * r * r;
  }
}

Stack and heap memory aliasing

Reference variables store only the reference (pointer) to the object allocated in heap memory:

Circle c1 = new Circle();
Circle c2 = c1; // c1 and c2 reference the EXACT SAME object in heap memory

c1.r = 10.0;
System.out.println(c2.r); // Prints 10.0

Initialization rules: Local vs. Class fields

Variable Scope Default Value Uninitialized Access Result
Local Variable (inside method) None Compile-time error (variable might not have been initialized)
Class Primitive Field 0, 0.0, or false Accessible with default value
Class Reference Field null Compiles, but causes runtime NullPointerException if dereferenced

3. Exam traps & common pitfalls

# Exam Pitfall Root Cause Remedy
1 Aliasing Mutation Bugs Assuming c2 = c1 duplicates the object rather than copying the pointer address. Instantiate a distinct object instance with new when independent state is required.
2 Uninitialized Local References Forgetting that local variables in Java do not receive default values like fields do. Always assign local variables before accessing or reading them.
3 Dereferencing Null Fields Attempting to invoke methods on reference fields that were never initialized. Initialize internal reference fields inside constructors or upon declaration.

4. Active recall flashcards

Question Answer
What mechanism enforces the abstraction barrier of a Java function? Its parameter types and return type.
What is the default initial value of a class reference field? null
What occurs when two reference variables point to the same heap object? Aliasing (mutating the object via one reference affects both).
What happens if you read an uninitialized local variable in Java? It results in a Compile-Time Error.
